# Assessments and Capstone

This file defines how to verify real competency across tech, AI, compliance, and clinical safety.

## Competency Scale

Use this scale for each domain:
- `L0`: No working understanding
- `L1`: Can explain concepts
- `L2`: Can execute with guidance
- `L3`: Can execute independently
- `L4`: Can review and improve others' work

## Domain Scorecard

Score every 4 weeks:
- Tech architecture and reliability
- AI evaluation and safety controls
- Compliance interpretation and evidence
- Clinical workflow literacy and escalation design
- Cross-functional communication quality

Target by end of Week 24:
- Minimum `L3` in all domains
- `L4` in at least one core domain (tech or AI or compliance)

## 4-Week Checkpoint Structure

For Weeks 4, 8, 12, 16, 20, 24:
1. Written review (`45 min`)
2. Practical implementation task (`2-3 hours`)
3. Evidence and risk review (`60 min`)
4. Retrospective (`30 min`)

## Sample Checkpoint Tasks

### Checkpoint A (Week 4)
- Written:
  - Explain how RLS prevents one realistic data leak in this system
- Practical:
  - Add one reliability improvement and show test proof
- Evidence:
  - Update threat model with one new risk and mitigation

### Checkpoint B (Week 8)
- Written:
  - Compare precision vs recall tradeoff for triage use-cases
- Practical:
  - Implement stricter output validation for AI response
- Evidence:
  - Record before/after failure cases

### Checkpoint C (Week 12)
- Written:
  - Explain how your model card communicates limitations
- Practical:
  - Add one monitoring signal for model drift or unsafe output
- Evidence:
  - Update model card and governance checklist

### Checkpoint D (Week 16)
- Written:
  - Explain intended use vs out-of-scope for AI assistant
- Practical:
  - Add one compliance control and associated audit log
- Evidence:
  - Add entry to evidence index

### Checkpoint E (Week 20)
- Written:
  - Describe emergency vs urgent escalation differences
- Practical:
  - Add red-flag handling improvement
- Evidence:
  - Show escalation policy updates

### Checkpoint F (Week 24)
- Written:
  - Present integrated risk posture and residual risks
- Practical:
  - Demonstrate capstone flow end-to-end
- Evidence:
  - Submit complete capstone dossier

## Capstone: Integrated Healthcare AI Governance Pack

Build and present a package containing:
- Product context and intended use statement
- Architecture and data-flow diagram
- Threat model and hazard log
- AI model card and evaluation report
- Compliance obligations matrix and implemented controls
- Clinical escalation policy
- Incident response runbook
- 90-day improvement roadmap

## Capstone Review Rubric

Score each from `0-5`:
- Technical rigor
- AI safety rigor
- Compliance completeness
- Clinical safety boundaries
- Evidence quality and traceability
- Communication clarity for non-technical stakeholders

Passing threshold:
- No category below `3`
- Overall average at least `4`

## If You Miss Targets

Remediation loop:
1. Identify one weak domain only (not all at once)
2. Repeat last 2 weeks of that domain with stricter output standards
3. Re-test with a new practical task
4. Document what changed in your operating behavior
